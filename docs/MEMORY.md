# 🧠 Memory

Dated decisions log, one line each, with the why.

- **2026-11-01** (#5): First market is Polish SMBs with a PL UI (udaina-style), not global solo founders, because it's a narrower, reachable audience and EN can be added later through Gettext.
- **2026-11-01** (#5): MVP (M1) is idea → AI plan → published landing page. The nightly autonomous loop is M2, because trust (activity log + undo) has to exist before agents act alone.
- **2026-11-01** (#5): LLM is the Claude API via Req behind a behaviour, so it can be mocked with Mox and swapped later.
- **2026-11-01** (#5): Integrations (inbox, ads, invoicing) are deferred to M3–M5 and are independent of each other, because each Polish integration is its own project.
- **2026-11-01** (#5): Issue #5 is docs only (PROJECT.md + STORIES.md). PLAN.md and pending specs wait for `/design`, because the open questions (site hosting, job library, research source) gate the task DAG.
- **2026-11-01** (#7): Auth is `mix phx.gen.auth Accounts User users --live`. Magic link is the primary flow and the generator's optional password is kept, because that means less custom code; "owner" is a role in the docs, not a table name.
- **2026-11-01** (#7): `/dashboard` ships as a placeholder LiveView (T2 after gen-auth T1), because AC2/AC4 need a protected landing page before M1 fills it.
- **2026-11-01** (#7): Auth tables keep phx.gen.auth's `timestamp` (utc_datetime) columns, not timestamptz, because the token expiry queries compare against `ago/2` (a timestamp param); timestamptz would make expiry depend on the DB session time zone.
- **2026-11-01** (#12): Polish is the Gettext backend's `default_locale`, not a per-request locale plug, because a language switcher is out of scope; EN msgids stay the source so untranslated copy falls back to English instead of raising.
- **2026-11-01** (#13): `Firmos.AI` resolves its adapter from app config at call time (not a module attribute), so test config can swap in `Firmos.AI.Mock` and no feature ever reaches the network.
- **2026-11-01** (#13): `Firmos.AI.Claude` returns errors as values (`{:http_status, s, summary}`, transport reason, `:missing_api_key`) and never raises, because AI calls will run inside LiveViews and Oban jobs where a crash would lose the owner's work; Req retries transient 5xx/429/timeouts twice, disabled in test.
- **2026-11-01** (#13): `ANTHROPIC_API_KEY` is required in prod but optional in dev, so the app boots locally without a key and AI calls answer `{:error, :missing_api_key}` instead of crashing.
- **2026-11-01** (#13): A 200 is only `{:ok, text}` on a finished turn with text; `refusal` → `{:refusal, details}`, `max_tokens`/context-window → `{:truncated, text}`, empty → `:empty_response`, because thinking eats `max_tokens` and a silently partial business plan is worse than an error. Default `max_tokens` is 16_000.
- **2026-11-01** (#15): The home-page idea is stored server-side as an `ideas` draft keyed by a random token (passed as `/users/register?idea=<token>`), not in the cookie session, because 2000 Polish characters can exceed the 4 KB cookie and magic-link sign-up may finish on another device; the token only reads that one unattached draft and is spent once the draft is attached to a user.
- **2026-11-01** (#15): `ideas.claimed_at` means "turned into a company" (set by STORY-006), not "attached to a user" (that is `user_id`), so `Ideas.latest_unclaimed_for_user/1` is the seam STORY-006 reads from.
- **2026-11-01** (#15): Idea length (20–2000) is counted in codepoints after trimming, matching the DB CHECK `char_length`, so the changeset and the constraint can never disagree on a grapheme-vs-codepoint edge case.
- **2026-11-01** (#16): The idea becomes a company when the owner lands on `/dashboard` (`Companies.ensure_company_from_idea/2` in mount, which turns every unclaimed idea into a company, oldest first, so the newest idea is the newest company regardless of visit count), not inside registration, because magic-link sign-up finishes in another request and possibly on another device; claiming with a conditional `UPDATE … WHERE claimed_at IS NULL` inside the insert's transaction makes the double LiveView mount and parallel tabs create exactly one company, with a unique index on `companies.idea_id` as the backstop.
- **2026-11-01** (#16): `companies.idea_id` is nullable with `on_delete: :nilify_all`, because companies can exist without an idea (STORY-011 adds more) and deleting an idea must never delete the company built from it.
- **2026-11-01** (#16): A new company's name is the translated placeholder "Moja firma", not a truncation of the idea, because a cut-off sentence makes a bad company name and the owner renames it on the profile; the web layer translates it and passes it in, so `Firmos.Companies` never depends on `FirmosWeb.Gettext`.
- **2026-11-01** (#14): Activity entries store `action` + structured `metadata` (old → new per changed field), not a rendered `summary` column, because a sentence frozen at write time can't follow the UI language; the web layer renders the summary through gettext, and no fallback text is needed since `action` is a closed `Ecto.Enum` and every value has a renderer.
- **2026-11-01** (#14): `Activity.record/4` is a plain insert the caller runs inside its own `Repo.transact`, not an `Ecto.Multi` helper, because `Companies` already uses `Repo.transact` and one function call is the smallest API for later stories (plan, site, undo); the entry rolls back with the change.
- **2026-11-01** (#14): Activity timestamps display in UTC with a "UTC" label, not Europe/Warsaw, because the stdlib has no tz database and adding `tz`/`tzdata` for one label isn't worth a dependency yet.
- **2026-11-01** (#14): New `activity_action` values are added by later stories with `ALTER TYPE activity_action ADD VALUE …` in their own migration (plus the `Ecto.Enum` list and a gettext renderer), so the enum grows without a lookup table.
- **2026-11-01** (#14): The activity page reads 50 entries at a time with a keyset `{inserted_at, id}` cursor (row comparison on the `(company_id, inserted_at DESC, id DESC)` index), not OFFSET, because the log only grows and offsets shift as agents write; the cursor stays in the socket, so "Load more" takes no client params.
- **2026-11-01** (#17): The first plan and its Oban job are inserted inside `ensure_company_from_idea/2`'s transaction (Oban's Postgres engine shares the Repo transaction), so a job exists only for a committed company and a rolled-back company leaves no orphan job.
- **2026-11-01** (#17): Plan generation never retries provider or parse failures (`{:cancel, code}`), because the Claude adapter already retries transient errors and one call can block ~30 min; `max_attempts: 2` exists only so Lifeline can resume a job orphaned by a node crash, and that second attempt may re-claim a stuck `generating` plan.
- **2026-11-01** (#17): `plans.error` stores a short safe code (`http_status:500`, `timeout`, `invalid_json`, …), never the provider's body or text, and the UI shows a generic translated message, so no provider detail or key can reach the owner or the DB.
- **2026-11-01** (#17): Plan content is one jsonb column typed by an embedded schema (`Firmos.Plans.Content`), not six columns, because the sections are read and written as one AI document and later stories may add sections without a migration.
- **2026-11-01** (#17): A `generating` plan untouched for 120 min is `Plans.stalled?/1` and can be retried or regenerated like a failed one, and a final worker attempt that crashes or can't store its result marks the plan failed, because otherwise a lost job leaves the owner with a plan that never finishes; 120 min outlasts the worst-case AI call (~30 min) plus Lifeline's 45-min `rescue_after` and a resumed attempt.
- **2026-11-01** (#18): A site's content lives in immutable `site_versions` rows and `sites.current_version_id` / `published_version_id` are pointers (composite FKs `(id, x) → site_versions(site_id, id)`, so a pointer can't reach another site's version), because STORY-009 edits and STORY-010 undo then become "insert version n+1 + move a pointer" with full history and no content rewriting.
- **2026-11-01** (#18): The AI returns structured JSON only (hero/offer/pricing/contact) and never HTML or URLs; the page is our HEEx `FirmosWeb.SiteComponents.landing/1` with everything escaped, and the contact email/city come from the company profile, not the AI, so a model can't inject markup, links or invented contact details.
- **2026-11-01** (#18): The draft preview is a plain controller with its own minimal `:site` root layout (no app chrome, no JS, `x-robots-tag: noindex`), not a LiveView, because STORY-009's public subdomain page must render through the same layout + component for "exactly as customers would see it" to hold.
- **2026-11-01** (#18): Site generation reads the company's *current* plan and fails with `no_ready_plan` if it is no longer ready when the job runs (e.g. regenerated meanwhile), rather than falling back to an older ready version, so the site never silently describes a plan the owner replaced.
- **2026-11-01** (#18): A site generation's claim token is the Oban job id (`sites.generation_job_id`, set by the claiming update): storing the version, storing `failed` and the worker's `mark_failed` all require it, because a status check alone let a stalled job that woke up after the owner asked again overwrite the newer generation; a stalled `pending` site (job died before claiming) can be re-requested too, since `mark_failed` no longer touches unclaimed sites.
